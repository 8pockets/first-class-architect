# 誤答を次の学習へ変える最小記録

決定日: 2026-08-04

根拠: [誤答を次の学習へ変える記録方法を決める](https://github.com/8pockets/first-class-architect/issues/9)

## 決定

誤答記録の目的を、間違いを保存することではなく、**次に行うインプットまたはアウトプットを一件へ絞ること**とする。

日付、学習項目、完了・中断・延期は通常の運用記録に任せる。誤答記録には、次の三つだけを追加する。

```text
原因: 主原因を一つ、または要再診断
観測差分: 自分の誤り・未生成 → 主教材で確認した正しい根拠
次回: 原因から自動的に決まる一件
```

`次回` は学習者が自由記述しない。原因ごとの対応表からCodexが決め、[再開キュー](https://github.com/8pockets/first-class-architect/issues/8)へ入れる。実施日は[間隔再テスト](https://github.com/8pockets/first-class-architect/issues/7)の規則で決める。

## 記録する場合

有効な問題で次のいずれかが起きた場合に一件だけ作る。

- 結論、理由、効いている条件の一つ以上が誤りまたは未生成だった
- ヒントまたは誘導質問を使った
- 制限時間内に回答できなかった
- 元の過去問には答えられたが、条件変更・概念識別・反例・初見統合で未合格になった
- 原理と条件は正しかったが、計算・読解・転記・マークの処理で誤答になった

外部から呼ばれた、通信が切れたなど、回答能力と無関係な中断では作らない。中断した正式な再テストは既決定どおり無効とし、別問題へ送る。

## 問題側を先に判定する

原因分類より先に、問題が有効か確認する。次のいずれかなら問題無効であり、学習者の誤答記録を作らない。

- 主教材から複数の結論が合理的に成り立つ
- 判断に必要な条件が固定されていない
- 想定解と主教材の参照箇所が一致しない
- 未学習の知識がなければ答えられない

無効理由を一文だけ作問側へ残し、条件を修正した別問題で同じ段階をやり直す。未合格回数、2回連続失敗、保持段階には数えない。

## 主原因の選び方

主教材で根拠を確認した後、次の境界を上から確認し、最初に証拠がある一つだけを選ぶ。

| 主原因 | 選ぶ境界 |
|---|---|
| 知識欠落 | 学習範囲にある必要な原理・式・用語を、最小の手掛かり後も説明できない |
| 因果誤解 | 要素や用語は知っているが、原因から結論までの向きまたはつながりが誤っている |
| 条件誤認 | 原理は説明できるが、成立条件、例外、適用条件を見落とすか取り違えた |
| 想起失敗 | 資料なしでは出なかったが、最小の手掛かり後は概念的な訂正なしで三点を説明できた |
| 転移失敗 | 既知の例は説明できるが、条件や表現が変わると原理を選択または適用できなかった |
| 処理ミス | 原理選択、理由、条件は正しく、計算、読解、転記、マークの操作だけを誤った |

複数のタグを付けない。概念上の誤りが確認できる場合は、表面的な転移失敗や処理ミスより、その知識・因果・条件の原因を選ぶ。

### 境界例

- 無回答の後、概念名だけで三点を正しく説明できた: 想起失敗
- 無回答の後、概念名を示しても原理を説明できなかった: 知識欠落
- 元問題は説明でき、条件変更後だけ原理を選べなかった: 転移失敗
- 変更後に適用できない条件そのものを誤解していた: 条件誤認
- 式、理由、条件は正しく、割り算だけを誤った: 処理ミス

観測が足りず区別できない場合は推測せず、要再診断とする。次の学習可能枠に、候補を分ける3分の診断質問を一問だけ置き、その結果で主原因へ置き換える。

## 原因から次の一件への変換

| 原因 | 当日の訂正 | 次の一件 |
|---|---|---|
| 知識欠落 | 主教材の原理一つと代表例一つへ戻り、閉じて三点説明する | 翌日、同じ段階の別問題で再テストする |
| 因果誤解 | 因果を一段ずつ確認し、逆条件も含めて訂正版を生成する | 因果の一箇所だけを変えた単一条件変更問題 |
| 条件誤認 | 適用する条件と適用しない条件を対にして訂正する | 混同した条件を使う概念識別問題 |
| 想起失敗 | 追加の読み込みをせず、概念名だけから三点説明を再生成する | 翌日、概念名だけを手掛かりに3分で三点説明する |
| 転移失敗 | 元問題と変形問題の変更条件・固定条件だけを比較する | 同じ転移段階で答えが異なる別問題 |
| 処理ミス | 誤った操作一箇所を訂正し、確認点を一つ決める | 同型の別問題を一問。繰り返す場合は確認手順を学び直す |
| 要再診断 | 未合格だった事実だけを残し、原因を推測しない | 候補を分ける3分の診断質問を一問 |

有効な問題への未合格は、原因にかかわらず間隔再テストの未合格回数へ数える。同じ段階で2回連続したら再学習へ戻るが、主原因に応じて学び直す対象を絞る。処理ミスなら教材全体を読み直さず、確認手順と代表問題一問を扱う。

## 観測差分の書き方

一文の中で、自分が生成した誤りまたは空白と、主教材で確認した正しい根拠を矢印で結ぶ。

```text
条件誤認 | 「鋼材強度を上げれば必ず増える」→「弾性座屈領域では強度に依存しない」 | 概念識別
```

```text
想起失敗 | 無回答 → 「iが大きいとλが小さくなり、座屈しにくい」を手掛かり後に再生 | 翌日3分想起
```

次のものは記録しない。

- 問題文や解説の全文
- 模範解答の書き写し
- 「ケアレスミスだった」「もっと頑張る」など、次の問題を変えない感想
- 同じ未合格への複数原因タグ
- ChatGPTが作った長い説明

## 60秒で終了する手順

根拠確認と訂正版の三点説明を終えた後、記録に使う時間は60秒を目安とする。

1. 学習者の初回回答と、主教材で確認した訂正版をChatGPTへ渡す。
2. ChatGPTは主原因一つと観測差分一文を提案する。正解根拠は作らない。
3. 学習者が提案を確認し、違えば修正する。
4. Codexは次の一件を対応表から決め、ローカルの学習状態へ保存する。

60秒で主原因を決める証拠がなければ、要再診断として終了する。分類のために朝30分を延長しない。

## 保存境界

GitHubへ置くのは、この分類規則と意思決定だけとする。実際の誤答記録は個人の学習履歴であり、教材の問題文・解説を複製せず、Codexがローカルの学習状態として管理する。ChatGPTの会話履歴は作業面であり、誤答記録の正本にはしない。

実際の保存形式、学習項目とのID連携、毎朝の再開キューへの自動投入は、[毎朝の学習セットとTODOを自動準備する](https://github.com/8pockets/first-class-architect/issues/13) で実装する。

## 試作品から得た結論

[使い捨てのロジック試作品](https://github.com/8pockets/first-class-architect/blob/prototype/issue-9-error-record/prototypes/issue-9-error-record/README.md) で8つの代表・境界ケースを操作した。

- 6つの主原因から、当日の訂正と次の一件を一意に選べた
- 無回答だけでは知識欠落と想起失敗を区別できず、要再診断が必要だった
- 問題無効を学習者の誤答記録から分離できた
- 処理ミスを概念全体の再読へ戻さず、確認手順と別問題へ送れた

試作品本体はmainへ取り込まず、分類規則と記録形式だけを正式決定として残す。
