# 説明できる理解を作るアウトプット形式

決定日: 2026-08-03

根拠: [説明できる理解を作るアウトプット形式を決める](https://github.com/8pockets/first-class-architect/issues/5)

## 主形式

朝は声を出せる環境ではないため、口頭説明を基本形にしない。資料を閉じ、ChatGPTへ次の三点説明を入力する。

新規学習の最初には、原理台帳を「原理名・自作2択問題・正解・結論・理由・結論を左右する条件」の順で隠さず読む。まずA/Bから結論を選び、その直後に正解と三点を確認する。その後、台帳と教材を閉じて次の三点を自分で再生成する。ここで隠すのは、別に出題する診断・変形問題の想定解とヒントであり、台帳の2択問題・正解と学習対象そのものではない。

```text
結論：
理由：
結論を左右する条件：
```

各項目は1〜2文に収める。文章を整えることではなく、資料なしで因果関係と成立条件を生成することを目的にする。

## 書けない場合

教材をすぐ開かず、説明が途切れた位置を具体的に残す。

```text
不明：〇〇と結論のつながりを説明できない
```

「分からない」だけでは終えない。この記述を最後の根拠確認と翌朝の繰り越しに使う。

## ChatGPTの応答

ChatGPTは三点説明を受け取っても、診断・変形問題の正解や模範文を先に示さない。最も大きな抜けまたは矛盾を対象に、問いを1つだけ返す。学習者が再回答した後、原理台帳と主教材で根拠を確認する。

説明が専門用語の言い換えだけになった場合に限り、「初学者にも分かるように、なぜそうなるか説明してください」と問い直す。他者へ教える説明を毎回の別課題にはしない。

## 条件付きの粗い図

荷重方向、変形形状、拘束位置などの空間関係が結論を左右する場合だけ、三点説明の6分枠内で2分以内の粗い図を1つ描く。毎朝の必須課題にはしない。

図は清書、撮影、保存、ChatGPTへの添付をしない。図から分かったことを三点説明へ文章で反映する。

## 訂正版

主教材で根拠を確認した後、資料を閉じる。元の投稿は編集せず、次の形式で新しいメッセージとして三点説明を再生成する。

```text
訂正版
結論：
理由：
結論を左右する条件：
```

初回と訂正版を両方残し、理解がどこで変わったかを見えるようにする。

## この決定に含めないこと

誤りの分類、次回課題への変換、長期保存の項目と保存先は、[誤答を次の学習へ変える記録方法を決める](https://github.com/8pockets/first-class-architect/issues/9) で決める。
