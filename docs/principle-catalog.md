# 鉄骨構造の原理台帳

決定日: 2026-08-10
更新日: 2026-08-13

## 目的

`2026_構造_文章問題.pdf` のPDF上P158〜P215にある鉄骨構造の知識を、過去問の答えではなく、自作2択問題と次の三点で事前に見渡し、学習後も改訂できる正本として残す。

- 結論
- 理由
- 結論を左右する条件

台帳では、一つの主要な結論とその理由・条件を一組で説明できる単位を一原理とする。出典確認済みの一原理につき、中心となる結論を一つだけ判断する自作2択問題を一問置く。複数の問題や解説に同じ原理が現れる場合は一件へ統合し、出典ページと問題コードを併記する。

表示順は `原理名 → 設問 → A/B → 正解 → 結論全文 → 理由 → 結論を左右する条件` とする。すべて折りたたまず常時表示し、回答入力、採点、保存は行わない。設問は対象と比較条件を明示して「正しい結論はどちらか。」で終え、選択肢は相反する短い結論を同じ文型で示す。各選択肢は40文字以内、A/Bの文字数差は10文字以内とする。誤選択肢は正解と一つの判断軸だけを反転し、教材外の知識・数値・例外を加えない。`必ず`、`絶対`、`両方`、`双方`、`いずれも`、`どちらも`、`どちらでもない`を正解の手掛かりに使わない。正解位置は各問の正本に固定し、116問全体をA58問・B58問とする。単純交互など次の正解を予測できる周期は使わず、同じ正解位置の連続も3問までとする。設問と両選択肢もサイト内検索の対象にする。

原理では変化の方向又は結果、規定では適用方法・数値・対象、識別では名称・定義・使い分けを選ばせる。一つの結論に複数の内容がある場合も、問題は中心判断一つに絞り、詳細は結論全文で確認する。教材内の根拠だけでは排他的な2択を作れない項目は問題を推測せず、`source_checked` から外して公開を止める。

正本では次の構造で問題を保存する。`correct` は表示時に並べ替えず、A/Bの固定位置をそのまま示す。

```yaml
question:
  prompt: 対象と条件について、正しい結論はどちらか。
  choices:
    A: 短い結論A
    B: 短い結論B
  correct: A
```

`manifest.yaml` には台帳総数215件、`source_checked` 116件、`source_gap` 97件、`draft` 2件と、正解位置A58件・B58件を固定する。さらに、独立内容監査で正解選択肢と結論・理由・条件の一致を全件確認した後の問題内容をSHA-256で固定する。項目の追加・削除、A/B、`correct` 又は三点を変える場合は、意味と出典を再監査してから件数と指紋を更新する。単なる自動再計算だけで監査済みとはしない。

## 対象と出典境界

- 対象: PDF上P158〜P215
- 種類: 因果関係を扱う `原理`、数値・適用条件を扱う `規定`、名称や使い分けを扱う `識別`
- 初版の根拠: 対象ページ内の記載だけ
- 教材に理由または条件が書かれていない場合: 推測で補わず `教材に記載なし` とする
- PDF本体、図版、原典の問題文、長い引用: リポジトリにも公開サイトにも保存しない
- 自作2択問題: `source_checked` の原理だけに作成して公開し、原典の問題文と混同しない表示にする

`data/principles/steel/` の章・節別YAMLを内容の正本とする。GitHub PagesのHTMLはこのYAMLから生成し、直接編集しない。

## 学習状態との境界

内容の正本と学習状態の正本を分ける。

- 原理の内容・出典: `data/principles/steel/`
- 詳細な学習状態: ローカルの `.study/state.json`
- 公開可能な粗い状態: `data/public_progress.yaml`

公開投影には `未学習`、`学習中`、`復習中`、`14日保持` だけを含める。実施日、回答、失敗回数、観測差分、次回期限は公開しない。

## 編集と公開

台帳には現在の最良版だけを置き、旧版はGit履歴で追跡する。変更時はコミットまたはPRに改訂理由を残す。自作2択問題の公開前には、正解選択肢が結論と一致すること、誤答が同じ一軸だけを反転すること、理由・条件の射程を超えないこと、原典問題文の複製でないことを、人が全件確認する。

公開サイトへ出すのは、自作2択問題を含む `source_checked` の原理だけとする。`draft` と `source_gap` は問題を作らずYAMLには残すが公開しない。サイトには公開件数と台帳化済み総件数を分けて表示する。

PRでは検証とサイト生成だけを行う。`main`へ取り込まれた変更だけをGitHub Pagesへ自動公開する。

初回設定として、2026-08-10にGitHub Pagesの公開元を `GitHub Actions`、サイト可視性を公開に設定した。この設定の存在だけを公開成功とはせず、各mainデプロイ後にActionsの完了と本番URLの内容を別々に確認する。

## 初版で保留した出典事項

- P181は鋼材強度が急低下する温度を「300℃超」、P205は長時間さらされる温度を「250℃以上」としており、対象範囲内では差を解消できない。対応する2件は `draft` とし、公開しない。
- P173の問題コード`01171`は根拠告示を「第464号」、同ページの`06162`は「第1464号」と記載している。台帳の因果関係はP209の説明でも確認したが、告示番号そのものは今後の原典確認事項とする。
- P197、P199、P209の一部は欄外の問題コードと本文の縦位置に幅がある。ページと候補は保持し、問題コードの一対一対応は次回の編集確認対象とする。
- 理由または条件が対象範囲にない項目は `教材に記載なし` として `source_gap` に残す。外部知識で埋めず、根拠を追加できた変更だけを将来 `source_checked` へ昇格する。

## ローカル操作

```sh
uv sync --group dev
uv run python -m principle_catalog validate
uv run python -m principle_catalog sync-study-items
uv run python -m principle_catalog sync-progress
uv run python -m principle_catalog study-brief S-K6-18-SLENDERNESS
uv run python -m pytest
uv run python -m principle_catalog build --output _site
```

`sync-study-items` は出典確認済みの新しいIDだけをローカル学習状態へ追加し、既存の進捗、キュー、開いているセットを変更しない。`study-brief` は出典確認済みの指定IDについて、設問、A/B、正解、三点を同じ順で初回学習前から表示し、未公開項目は受理しない。`sync-progress` はローカル学習状態から公開可能な粗い状態だけを再生成する。生成後も、差分に詳細な学習情報が含まれていないことを検証してから公開する。
