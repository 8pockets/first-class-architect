# 鉄骨構造の原理台帳

決定日: 2026-08-10
分類・表示契約改訂日: 2026-08-14

## 目的

`2026_構造_文章問題.pdf` のPDF上P158〜P215にある鉄骨構造の知識を、過去問の答えの羅列ではなく、判断、根拠、適用境界を一組にした正本として残す。

台帳の公開画面は、内容を初回学習前から読み、後で資料なしに再生成するための参照面である。回答を保存する試験画面にはしない。教材本文、原典問題文、図版、個人の回答、詳細な学習履歴は公開しない。

内容監査の根拠と移行判断は、[鉄骨構造台帳の内容レビュー](./steel-catalog-content-review.md)に残す。

## 一項目の単位

一項目は、確認問題で一つの判断を求め、本文でその判断の根拠と境界を説明できる単位とする。広い用語見出しや、独立した複数結論の詰め合わせにはしない。同じ判断が複数の問題や解説に現れる場合は一項目へ統合する。

内容は次の三種類に分け、公開時の三点見出しを変える。

| 種類 | 第1欄 | 第2欄 | 第3欄 |
|---|---|---|---|
| 原理 | 結論 | 理由 | 結論を左右する条件 |
| 規定 | 規定 | 適用範囲 | 数値・例外 |
| 識別 | 定義 | 識別条件 | 混同注意 |

既存データとの互換性と監査来歴のため、全項目に `conclusion`、`reason`、`conditions` を残す。公開する規定は `rule`、`applicability`、`numbers_exceptions`、公開する識別は `definition`、`distinguishing_conditions`、`confusable_points` を `display_content` へ明示する。既存の理由や条件を別の意味の見出しへ機械的に読み替えない。公開規定・識別に型別データがなければ、Pages生成を失敗させる。

第3欄に出典で確認できる数値・例外又は混同注意がない場合も見出しは省略せず、推測を足さずに `—` と表示する。

## 表示分類と出典来歴を分ける

`data/principles/steel/` の章別YAMLは、教材から抽出した物理的な保管単位として残す。Pagesの分類は `taxonomy.yaml` の投影を正本とし、全有効項目を次の7群・37小項目へ一度ずつ割り当てる。

1. 架構・鋼材・許容応力度
2. 梁・柱・座屈
3. ボルト接合
4. 溶接接合
5. ブレース・耐震
6. 柱脚・仕口・継手
7. 耐火・特殊荷重

出典ページ、本試験知識表の問題コード、旧章名、外部一次資料は、分類ではなくカードの来歴と絞込み条件として扱う。従来の `本試験知識（横断）` は表示分類から廃止し、旧見出しへのリンクには再配分先の索引を返す。

## 公開表示

表示順は、原則として次のとおりとする。

1. 内容名、公開コード、種類、学習状態
2. 確認問題（自作・2択）とA/B
3. 正解
4. 種類別の三点
5. 教材ページ、問題コード、外部一次資料

正解と三点は、初回学習前から常に表示する。開示操作、開閉状態、回答、採点は持たない。検索対象には内容名、問題、選択肢、正解、三点、公開コード、出典を含める。

設問は対象と比較条件を明示して「正しい結論はどちらか。」で終え、選択肢は相反する短い結論を同じ文型で示す。各選択肢は40文字以内、A/Bの文字数差は10文字以内とする。誤選択肢は正解と一つの判断軸だけを反転し、教材外の知識、数値、例外を加えない。`必ず`、`絶対`、`両方`、`双方`、`いずれも`、`どちらも`、`どちらでもない`を正解の手掛かりに使わない。

## 内部キー、公開コード、旧別名

識別子の役割を分ける。

- `key`: 既存の `S-K6-*`。学習状態、前提関係、版台帳が参照する不変の内部キー
- `code`: `structure.steel.<semantic-slug>`。利用者が読む意味ベースの公開コード
- `alias`: 発行済みの旧キー、旧公開コード、旧固定リンクを解決する無期限の別名

分類番号、表示順、PDFページ、問題番号、内容種別、公開状態を公開コードへ埋め込まない。通常の名称変更では内部キーを変えない。

統合前の旧キーは、新しい一項目へ解決する。分割前の旧キーは、後世代で移行先が一項目へ収束しても、分割の来歴を残す索引として扱い、一方へ黙って転送しない。中央の識別子解決器をPages、CLI、学習状態投影で共用する。

退役項目の移行台帳には旧セクションも保存する。従来の `#section-K6-*` でアクセスした場合は、現在の小項目への移行先を表示する。Pagesへ互換経路を出すのは問題版で一度でも発行した識別子だけとし、一度も公開していない `source_gap` 又は `draft` を退役しても、その内部キー、コード、別名を新たに公開しない。公開コード、旧別名、移行経路、旧セクションは独立した監査ハッシュと履歴比較で固定し、発行後の削除・付替えを認めない。

既存の `.study/state.json`、`.study/results.jsonl`、保存済み学習セットは書き換えない。一対一移行は既存の進捗を保ち、統合項目は保守的に再確認対象とし、分割した子項目は未確認から始める。旧項目の履歴は削除しない。

## 前提、関連、表示順

`prerequisites` は、その項目を理解する前に必要な硬い学習依存だけに使う。順序を近付けたいだけの関係は `related` に置く。

表示順は、7群・37小項目を基本の並びとして、前提が依存項目より前に来る安定トポロジカル順で生成する。内部キーやYAMLの物理順を学習順の代わりにしない。

公開項目は前提閉包を満たし、公開カードが非公開カードを前提にしない。循環、欠落、表示順違反をCIで拒否する。

## 導入層

公開問題は、重要度又は個人難易度ではなく、理解へ導入する範囲を表す版付きの`coverage tier`へ一度だけ所属させる。初版は次の累積三層とする。

| 層 | 名称 | 初版件数 | 役割 |
|---:|---|---:|---|
| 1 | 骨格 | 32 | 公開問題がある32小項目の代表を一件ずつ置き、全体地図を作る |
| 2 | 標準 | 42 | 通常条件、基本規定、基本識別、標準的な適用を追加する |
| 3 | 発展 | 42 | 例外、細部、特殊条件、統合判断を追加する |

利用時は骨格、骨格と標準、全件の順で累積表示する。初版は各層のA/Bを同数とし、問題種別は台帳全体の構成比へ近付ける。`tier(prerequisite) <= tier(dependent)`を必須とし、同じ層では前提を先に導入する。導入順は、前提を満たす各大項目から最大一件ずつ選ぶ小周回とし、同じ正解の連続を三件以下にする。

層の判定理由は、小項目代表、後続の前提、標準適用、基本識別、例外・細部、統合判断の定型値で保存する。問題コード参照数、前提数、条件数を合算した単一スコアでは決めない。新しく公開された項目は適切な層へ追加し、公開問題がなかった小項目の最初の代表は骨格へ置く。分割又は統合では層を自動継承せず、新しい判断単位ごとに再判定する。

層分類は問題版と分離した版として保存する。既発行の分類版は変更せず、修正時は新しい分類版を追加する。`K6-R2`の番号、7群・37小項目の既定表示順、固定リンクは層によって変更しない。Pagesは全件を初期表示し、骨格のみ又は標準までの累積フィルタを提供する。耐火・特殊荷重は、根拠確認済みの公開問題がない間は件数だけを根拠確認待ちとして示す。

導入層は新規項目の候補順にだけ使う。再学習、翌日再テスト、期限超過、当日期限、中断の既存キューを追い越さない。前層の全項目が初回導入済みになった後で次層を解放し、14日保持までは待たない。個人難易度は最低三回、うち一回以上の日を空けた想起結果がある場合だけ非公開状態として別に観測し、固定層を動かさない。

## 問題版と印刷

Q番号は項目の識別子ではなく、発行済み問題版の参照番号とする。

- `K6-R1`: 従来のQ001〜Q116をそのまま保存した過去版
- `K6-R2`: 分類、粒度、前提順を反映した現行版
- 公開後の項目追加、削除、並び変更: `K6-R3` のような新しい版を発行

現行・過去を問わず、発行済み版の割当て、番号、監査ハッシュは変更しない。過去版は、統合・分割で退役した内部キーを参照してよい。表示上の通し番号と版付き参照を分け、例えば `問12 [K6-R2 Q087]` と示す。検索や絞込みで版付き参照は変えない。

印刷時は画面で表示中の問題だけを対象にし、正解、三点、内容名、分類、種類、学習状態、出典を出さない。A4縦、余白8mm、9pt、縦読みの2段組みで、各問を途中分割せず、通し番号、版付き参照、問題文、`□ A`、`□ B`だけを白黒で配置する。サイト内に印刷ボタンは置かず、ブラウザの印刷機能を使う。

## 出典と公開判定

対象範囲はPDF上P158〜P215である。教材内の根拠に加え、必要に応じて次の外部一次資料だけを使う。

- 法令
- 告示
- JIS
- 日本建築学会の規準・指針
- 国の標準仕様書

各外部出典には、資料名、位置、URL又は識別情報と、それが `statement`、`explanation`、`conditions` のどこを支えるかを記録する。検索結果、出典のない解説記事、AIの説明は根拠にしない。

内容監査は次を別々に記録する。

- `statement_source`: 主張の根拠が確認済み、欠落、未監査のどれか
- `explanation_completeness`: 説明が完全、部分的、不足、未監査のどれか
- `conditions_completeness`: 条件が完全、部分的、不足、未監査のどれか

公開するのは、独立した自作2択問題を持ち、公開条件を満たす `source_checked` 項目だけとする。`source_gap` と `draft` はYAMLへ残すが、Pagesには出さない。外部資料で主張だけを確認できても、理由又は条件を推測で補完しない。

## 監査スナップショット

分類改訂前は、総数215件、`source_checked` 116件、`source_gap` 97件、`draft` 2件であった。6分割・4統合後は総数216件となったが、分割後の一項目で教材内の独立根拠を確認できなかったため非公開へ戻した。初回移行版は `source_checked` 116件、`source_gap` 98件、`draft` 2件を基準とする。

内容、分類、前提、表示順、識別子、移行経路は別々のSHA-256で固定する。意味変更を伴う編集では、該当する監査を人が行ってから対応するハッシュと件数を更新する。単なる自動再計算だけで監査済みとはしない。

P181とP205にある高温時の温度記述の差、P173にある告示番号の差、欄外問題コードと本文の位置が曖昧なページは、解消するまで監査事項として残す。

## 学習状態と公開境界

内容の正本と学習状態の正本を分ける。

- 内容、分類、識別子、問題版: `data/principles/steel/`
- 詳細な学習状態: ローカルの `.study/state.json`
- 公開可能な粗い状態: `data/public_progress.yaml`

公開投影には `未学習`、`学習中`、`復習中`、`14日保持` だけを含める。実施日、回答、失敗回数、観測差分、次回期限を公開しない。

## 編集、検証、公開

変更時は、正解選択肢が本文と一致すること、誤答が同じ一軸だけを反転すること、三点が出典の射程を超えないこと、原典問題文を複製していないことを確認する。

主なローカル操作は次のとおりである。

```sh
uv sync --group dev
uv run python -m principle_catalog validate
uv run python -m principle_catalog verify-identity-history --previous-identities PATH --previous-migration PATH
uv run python -m principle_catalog verify-question-editions --previous PATH
uv run python -m principle_catalog verify-coverage-tiers --previous PATH
uv run python -m principle_catalog sync-study-items
uv run python -m principle_catalog new-study-candidates --state .study/state.json
uv run python -m principle_catalog sync-progress
uv run python -m principle_catalog study-brief structure.steel.compression-member-slenderness
uv run python -m pytest
node --check principle_catalog/static/catalog.js
node --test tests/catalog-interactions.test.mjs
uv run python -m principle_catalog build --output _site
```

`study-brief` は内部キー、公開コード、一対一の旧別名を受け付け、問題、正解と三点を常に表示する。旧 `--reveal` は既存コマンド互換のため受理するが、表示内容を変えない。複数へ分割された旧別名は移行先を示し、一件として実行しない。

`sync-study-items` は公開済みの新しい内部キーだけをローカル学習状態へ追記し、既存の進捗、キュー、開いているセット、退役項目の履歴を変更しない。`sync-progress` はローカル状態から公開可能な粗い状態だけを再生成する。

`new-study-candidates` は、既存の再開キューで新規学習が許可された場合に使う候補一覧である。現在解放されている導入層までの未学習項目だけを小周回順で示し、学習状態は変更しない。

PRでは検証とサイト生成だけを行う。`main`へ取り込まれた変更だけをGitHub Pagesへ自動公開し、Actionsの成功と本番URLの内容を別々に確認する。
