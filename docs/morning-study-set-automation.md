# 毎朝の学習セット自動準備

決定日: 2026-08-05

根拠: [毎朝の学習セットとTODOを自動準備する](https://github.com/8pockets/first-class-architect/issues/13)

試作品: [毎朝の学習セット割当てを試作したDraft PR](https://github.com/8pockets/first-class-architect/pull/24)

## 決定

毎日5時30分（Asia/Tokyo）に、この学習プロジェクトの同じChatGPT/Codexタスクを起こすHeartbeatを実行する。実行時にローカルの学習状態、前回の明示結果、復習期限、教材の利用可否を確認し、その日に行う一件を**準備済み学習セット**として会話へ表示するとともに、ローカルへ保存する。

学習セットは、朝30分、昼5分、通勤中の任意一件、最低5分の四欄を持つ。新規学習では、原理台帳の原理名、確認問題（自作・2択）、A/Bだけを最初に表示する。学習者がA/Bを選んだ後、明示的な開示段階で正解、結論、理由、結論を左右する条件を表示し、5〜12分の狭い入力として読む。別に出題する診断・変形問題については問題、教材の参照位置、終了条件だけを表示し、その問題の想定解、模範説明、ヒント、教材本文は、学習者の初回回答より前に表示しない。

自動準備は教材担当であり、学習そのものではない。セットを生成しただけで、実施、合格、保持、欠席を記録しない。前回結果を確認できない場合は完了を推測せず、前回セットを再開セットとして出す。

## 自動化の位置づけ

| 項目 | 決定 |
|---|---|
| 名称 | `First-Class Architect Morning Study Set`（朝の学習セット） |
| 自動化ID | `first-class-architect-morning-study-set` |
| 種類 | 現在の学習タスクへ継続するHeartbeat |
| 実行時刻 | 毎日5時30分、Asia/Tokyo |
| 実行先 | この学習プロジェクトの同じタスク |
| 出力先 | タスクへのメッセージとローカルの当日セット |
| 正本 | ローカルの学習状態と明示結果 |
| 初期対象 | 構造パイロットを起点にした鉄骨構造、PDF 158〜215ページ |
| 通知 | 成功時も当日のセットを表示する |

毎回新しいタスクを作らない。前日の回答、未完了、期限超過と同じ文脈を引き継ぎ、一つのタスクで学習対話を続ける。

## 保存境界

個人の学習状態はリポジトリ内の次の無視対象へ置く。

```text
.study/
├── state.json
├── results.jsonl
└── sets/
    ├── latest.md
    └── YYYY-MM-DD.md
```

- `state.json`: 学習項目、段階、実際の通過日、次回期限、連続未合格、未完了セット
- `results.jsonl`: 学習者が明示した一回ごとの結果。追記だけを行う
- `sets/YYYY-MM-DD.md`: その日に表示した台帳入力と答えなしの診断・変形問題
- `sets/latest.md`: 自動準備全体が失敗した場合にも開ける直近セット

`.study/`はGit管理しない。GitHubにはこの運用規則、原理台帳の自作2択問題、集計値、採用・修正・中止の判断だけを置く。教材本文、原典問題文の複製、回答、誤答差分、日々の詳細結果を置かない。

ChatGPTの会話履歴は学習対話と結果入力の窓口であり、学習状態の正本ではない。Codexは、学習者が明示した結果だけをローカル状態へ反映する。

## 学習項目の識別

学習項目の正本は `data/principles/steel/` の原理台帳とする。各項目は安定IDを持ち、ローカルの `.study/state.json` は同じIDで詳細な学習状態を結び付ける。教材本文ではなく、項目ID、概念名、参照位置だけを状態へ保存する。

次の四項目は構造パイロットから引き継ぐ保持アンカーであり、今後の新規項目はPDF 158〜215ページの台帳から追加する。

| 項目ID | 概念 | 参照位置 | 初期役割 |
|---|---|---|---|
| `S-K6-18-SLENDERNESS` | 全体座屈と細長比 | PDF 193ページ | 最初の新規項目、保持対象1 |
| `S-K6-18-ELASTIC-STRENGTH` | 弾性座屈領域と鋼材強度 | PDF 193ページ | 二番目の新規項目、保持対象2 |
| `S-K6-19-LATERAL-BUCKLING` | 梁の横座屈 | PDF 194ページ | 三番目の新規項目 |
| `S-K6-20-LOCAL-BUCKLING` | 局部座屈と幅厚比 | PDF 195ページ | 四番目の新規項目 |

主教材は次のローカルファイルとする。

```text
/Users/shin/Documents/一級建築士勉強教材/合格ロケット_2026.py/download.py/構造/2026_構造_文章問題.pdf
```

ファイルが存在しても、指定ページから問題の想定解と根拠を一意に確認できなければ、有効問題を生成できたことにしない。

## 自動準備が読む入力

次の順で入力を確認する。

1. 現在日時と曜日。平日か休日かを判定する
2. 同日分のセットが既に生成済みか
3. `.study/state.json` と `.study/sets/latest.md` が存在し、読み取れるか
4. 前回セット以降に、学習者がこのタスクへ明示した結果があるか
5. 2回連続未合格による再学習、翌日再テスト、期限超過、当日期限、中断、新規候補の順で再開キューを作る
6. 主教材の絶対パスと対象ページを読めるか
7. `data/principles/steel/` から対象IDの自作2択問題とA/Bを初回入力として表示でき、A/B選択後の明示操作に限って正解と三点を開示できるか
8. 転移問題の想定解、根拠、変更条件、固定条件を主教材から内部確認できるか

前回結果が自然文で書かれていても、実施・結果・ヒント使用を一意に読み取れない場合は推測しない。状態を更新せず、前回結果未記録として扱う。

## 結果入力

学習後は、当日セットへの返信として次の一行だけを最低入力とする。日付と項目IDは開いているセットから補う。

```text
結果 | 主学習・縮退・欠席 | 完了・中断・延期 | 三点○・×・未実施 | テスト○・×・無効・未実施 | ヒントなし・あり
```

例:

```text
結果 | 主学習 | 完了 | 三点○ | テスト× | ヒントなし
```

- `×`の原因を一つに決める証拠が会話にない場合は、要再診断とする
- `無効`は学習者の未合格回数へ入れず、別問題を作る
- `中断`は正式テストの不合格にせず、別問題または未完了工程へ送る
- `欠席`は夜へ移さず、次の予定機会の再開キューへ送る
- ヒントありで訂正できても、正式な転移・保持合格にはしない

自動準備は、結果一行を確認した後にだけ `results.jsonl` へ一件追記し、`state.json` を更新する。同じセットIDの結果は一回だけ反映する。

## 再開キューと枠への割当て

優先順位は次で固定する。

1. 2回連続未合格による再学習
2. 前回未合格になった段階の翌日再テスト
3. 最も古い期限超過の間隔再テスト
4. 当日期限の間隔再テスト
5. 中断した学習の再開
6. 新しい原理の基本学習ループ

新規候補は、未学習かつ前提原理がすでに学習対象へ入っているものから、PDFの節・ページ順で選ぶ。一日の新規単位は中心となる原理一件を基本とし、それ単独では意味が切れる場合だけ、不可分な規定または識別を二件まで添える。進捗はまとめず、各IDへ個別に記録する。

### 平日

- 再学習、翌日再テスト、期限超過、中断がある場合は、先頭一件を朝へ置き、新規項目を追加しない
- 二件目が5分以内なら昼へ置く。三件目以降は翌日以降へ送る
- 当日期限の3分または5分再テストだけなら、朝は新規一件、昼は再テスト一件にする
- 8分の初見統合と再学習は朝へ置く
- 通勤中は昼と同じ一件を、安全に座って文字入力できる場合だけ任意表示する

### 休日

- 昼と通勤へ項目を置かない
- 期限項目があれば一件だけ朝へ置き、新規項目を追加しない
- 期限項目がなければ朝の新規一件または再開一件だけを出す

どちらも夜の埋め合わせを作らない。各枠へ一件を超えて割り当てない。

## 通常の出力形式

```text
# 今日の学習セット YYYY-MM-DD
状態: READY / REUSE / FALLBACK
セットID:
開始: このメッセージを開いたら教材選びをせず、使える時間だけ選ぶ

## 朝30分
項目ID・概念・教材ページ
0〜5分: 遅延想起または初日の事前診断
5〜12分: 狭い入力（下の自作2択問題を選び、明示開示後に正解と台帳の三点を読む）
12〜18分: 資料なしの三点説明
18〜26分: 診断・変形問題一問
26〜30分: 根拠確認後に資料を閉じ、訂正版を再生成
終了条件:

## 事前に読む原理台帳
原理:
確認問題（自作・2択）:
A:
B:
回答後の開示: A/Bを選んだ後にのみ正解と三点を表示する

## 今日の一問
問題文だけ
回答形式: 結論 / 理由 / 効いている条件

## 昼5分
一件または割当てなし

## 通勤中（任意）
安全に座って操作できる場合だけ。必須にしない

## 最低5分
3分想起 / 1分根拠確認 / 1分結果記録

## 終了時の返信
結果 | ...
```

回答後の明示的な開示は、初回出力と分けて次の形式で返す。

```text
## 回答後に開示する原理台帳
正解:
結論:
理由:
結論を左右する条件:
```

初回出力には、教材を開くページと見出し、および対象IDの原理台帳にある自作2択問題とA/Bだけを含める。正解と三点は、学習者がA/Bを選んだ後に開示を求めた場合だけ同じ順で表示する。自動準備が先回りして開示したり、開閉を回答・進捗として記録したりしない。どちらの段階にも含めないのは、別枠の「今日の一問」に対する想定解、正解方向、使う式、ヒント、採点チェックポイント、教材本文の引用である。ChatGPTは学習者の三点回答を受け取るまで、問い返す場合も一問だけにする。

## 一日一セット

同じ日付のセットが既にあり、学習状態に新しい明示結果がなければ、再実行しても新しいセットを作らない。既存の `YYYY-MM-DD.md` を再表示する。

同日中に学習を完了しても、次の日のセットを先に作らない。次のHeartbeatが、実際の結果と通過日から復習期限を計算する。原理台帳の原理名、問題、A/Bはいつでも先に閲覧できるが、正解と三点はA/B選択後の明示操作まで開示しない。次回の診断・変形問題とその想定解も先に表示しない。

## 初回起動

`state.json` も `sets/latest.md` も存在しない場合だけ、初回起動とする。最初の項目は `S-K6-18-SLENDERNESS` とし、遅延想起5分を事前診断5分へ置き換える。

状態ファイルがない一方で `latest.md` が残っている場合は、初回へ戻さない。状態消失として新規学習を止め、直近セットの概念名を使う5分フォールバックだけを出す。

## フォールバック

### 前回結果が未記録

- 前回セットを `REUSE` として表示する
- 完了済みなら結果一行だけを先に求める
- 未完了なら記録済みの中断工程から再開する
- 新規項目、次段階、復習合格を作らない

### 主教材が読めない

- 正式な新規学習と再テストを止める
- 直近概念名から3分だけ資料なしで三点説明する
- 教材確認を要求せず、1分で「主教材を確認できず」と記録する
- 残り1分で次の一件を残し、段階を進めない

### 有効な問題を生成・検証できない

- 作問を推測で補わない
- 主教材が読める場合だけ、直近概念の3分想起、1分根拠確認、1分記録を出す
- 正式な転移・保持結果へ数えず、問題生成の失敗として残す

### 自動化そのものが実行されない

- `.study/sets/latest.md` を開く
- そこにある「最低5分」だけを行う
- 次回実行時に `自動準備失敗` として明示し、学習者の欠席・未合格にはしない
- `latest.md` もなければ、PDF 193ページを開かず「全体座屈と細長比」を3分で説明し、進捗を付けず終了する

### 重複実行

- 当日セットを再表示するだけにする
- セットID、結果、次回期限を重複作成しない

## 書き込みの安全境界

- 自動準備はGit操作、Issue更新、PR作成、教材PDFの変更を行わない
- `.study/`以外のローカルファイルを変更しない
- 学習者の明示結果がない状態で、完了、合格、未合格、欠席を作らない
- 問題無効と生成失敗を学習者の失敗へ入れない
- 既存結果を削除または上書きせず、訂正は新しい記録として追記する
- 30分を超える課題、夜の埋め合わせ、危険な通勤操作を割り当てない

## 運用の確認

自動化の作成、ACTIVE表示、保存された時刻は、毎朝の実行成功そのものではない。最初の予定実行後に、次を別々に確認する。

1. Heartbeatが予定時刻に実行された
2. その日のセットがタスクへ表示された
3. `.study/sets/YYYY-MM-DD.md` と `latest.md` が一致する
4. 前回結果がない場合に新規項目へ進まなかった
5. 初回セットには原理台帳の自作2択問題とA/Bだけが表示され、A/B選択後の明示操作で初めて正解と三点が表示された
6. 診断・変形問題の想定解、ヒント、教材本文は初回回答前に表示されなかった

予定実行の証拠を確認するまでは、「自動化設定済み」と報告し、「毎朝の実行確認済み」とは報告しない。

## 試作品から得た結論

[使い捨てのロジック試作品](https://github.com/8pockets/first-class-architect/pull/24)で、初回、期限項目、重複キュー、前回未記録、教材不在、生成失敗、休日、状態消失、同日重複実行の九ケースを操作した。

最初の試行では、休日の期限項目が朝へ移らない、教材不在なのに根拠確認を要求する、状態消失を初回起動と誤認し得る三つの問題が見つかった。修正後の再試行で、各ケースを進捗の推測なしに `READY`、`REUSE`、`FALLBACK`へ分けられた。

試作品本体はmainへ取り込まず、この運用規則だけを正式決定として残す。
