# 数日後の再現を測る間隔復習

決定日: 2026-08-04

根拠: [数日後の再現を測る間隔復習を決める](https://github.com/8pockets/first-class-architect/issues/7)

## 位置づけ

同じ朝に訂正版を再生成できただけでは、数日後の保持を確認できない。初回学習後に間隔を空け、資料・解説・ヒントなしの三点説明と転移テストを段階的に行う。

以下の日程は学習科学から一意に決まる最適値ではなく、2週間の構造パイロットで実行可能性と失敗率を検証する初期設定である。

## 初期日程と内容

初回学習日を0日目とし、予定どおり通過した場合は次の日程になる。

| 時点 | 上限 | 再テスト |
|---:|---:|---|
| 1日後 | 3分 | 概念名だけを手掛かりに、問題文なしで三点説明する |
| 3日後 | 5分 | 単一条件変更問題を1問解く |
| 7日後 | 5分 | 概念識別問題を1問解く |
| 10日後 | 5分 | 主教材に境界・例外がある原理だけ、反例問題を1問解く |
| 14日後 | 8分 | 初見統合問題を1問解く |

反例問題を作れない原理は10日後を省略する。同じ問題を再利用せず、各回1問・1原理に限定する。上限時間が来たら打ち切り、時間延長で合格を作らない。

## 日付の動かし方

`1・3・7・10・14日後` は、すべて予定どおり通過した場合の表示である。実際には、前段階をヒントなしで通過した日を基準に次の間隔を空ける。

- 初回学習から最初の三点説明まで1日
- 三点説明から単一条件変更まで2日
- 単一条件変更から概念識別まで4日
- 反例がない場合、概念識別から初見統合まで7日
- 反例がある場合、概念識別から反例まで3日、反例から初見統合まで4日

欠席や再テスト失敗で前段階が遅れた場合、後続日程も実際の通過日から後ろへずらす。間隔を詰めて元のカレンダーへ追いつこうとしない。

## 合格条件

各回とも、資料、解説、ヒント、誘導質問を使わず、制限時間内に次の3点がすべて正しい場合だけ合格とする。

1. 結論
2. 原理に基づく理由
3. 結論に効いている条件

1日後の三点説明では、原理の結論、因果関係、成立条件として判定する。表現の上手さや文章量は採点しない。

途中でヒントを使った場合や時間切れは、訂正できても間隔再テストとしては未合格とする。作問側に複数解、条件不足、参照不一致、未学習知識がある場合は問題を無効とし、学習者の失敗には数えない。

## 未合格時

未合格になった日は主教材で根拠を確認し、資料を閉じて訂正版の三点説明を行う。翌日に、答えの異なる別問題で同じ段階を再テストする。合格するまで上の段階へ進めない。

同じ段階で2回連続して未合格になった場合は、テストを繰り返さず再学習へ戻す。次の学習可能日に、主教材から原理1つと代表例1つを学び直し、その日を新しい0日目として日程を再開する。

## 欠席と重複

予定日に実施できなかったこと自体は失敗としない。対象を「期限超過」として次の学習可能日へ移し、後続間隔は実際の通過日から数える。

複数の再テストが同じ日に重なった場合は、次の順で1件ずつ処理する。

1. 前回未合格で翌日再テストになった原理
2. 最も古い期限超過の原理
3. 当日が期限の原理

1つの復習枠へ詰め込まず、残りは翌日以降へ送る。朝・昼休み・通勤中のどの枠へ置くかは、[疲れた日でも続く学習運用を決める](https://github.com/8pockets/first-class-architect/issues/8) で決める。

## 14日保持の判定

必要な段階をすべて通過し、最後の初見統合問題も資料・ヒントなしで合格した原理を「14日保持」とする。途中で未合格になっても、訂正・再学習後に全段階を通過すれば判定できる。

14日保持は、2週間後にも原理を使えたというパイロット上の状態であり、試験日までの永久的な定着や復習不要を意味しない。
