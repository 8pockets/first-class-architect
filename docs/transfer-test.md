# 過去問暗記を見抜く転移テスト

決定日: 2026-08-04

根拠: [過去問暗記を見抜く転移テストを決める](https://github.com/8pockets/first-class-architect/issues/6)

## 目的

元の過去問への正答だけでは、問題固有の手掛かりと答えを記憶した状態を除外できない。転移テストでは、学習済みの同じ原理を異なる条件や状況で使わせ、結論・理由・効いている条件を資料なしで生成できるか確認する。

朝の診断・変形問題8分では、1回につき転移テストを1問だけ扱う。4種類を同じ朝に解く運用にはしない。

## 問題型と進行

### 1. 単一条件変更問題

標準の問題型。他の条件を固定し、結論に効く条件を1つだけ変える。変更後の結論、理由、変えた条件を答えさせる。

数値や固有名詞だけを変え、同じ答えを再生できる問題は転移テストにしない。

### 2. 概念識別問題

単一条件変更問題に合格した後の必須段階。混同しやすい現象や規定から、与えられた条件に適用するものを選び、理由と識別条件を答えさせる。「類題」という名称は使わない。

### 3. 反例問題

主教材に明確な境界または例外がある場合だけ必須にする。「常に」「大きいほど必ず」などの一般化が成り立たない条件と理由を答えさせる。根拠のない反例を無理に生成しない。

反例を主教材から作れない原理は、概念識別問題に合格すれば次の段階へ進める。

### 4. 初見統合問題

最後の段階。学習済みの関係を2つ組み合わせ、条件同士が同じ方向または反対方向へ働く新しい状況を判断させる。未学習の事実がなければ答えられない問題は、新規インプットであって転移テストではない。

## 作問条件

ChatGPTまたはCodexが問題を作るときは、学習者へ最初は見せない確認情報として、次の4項目を用意する。

- 想定する結論
- 根拠となる原理
- 変更した条件と固定した条件
- 主教材の参照箇所

回答が主教材から確認できない問題、新しい知識を追加した問題、単なる言い換えは使わない。問題文には、想定解を推測できる誘導や不要なヒントを含めない。

## 1問の合格条件

資料、解説、ヒント、誘導質問を使わず、次の3点がすべて正しい場合だけ合格とする。

1. 結論
2. 原理に基づく理由
3. 結論に効いている条件

結論だけが正しい場合は、答えの記憶や推測を除外できないため未合格とする。文章の長さや表現の上手さは採点しない。

途中でヒントを使った場合、訂正できたことは学習成果として扱うが、転移確認は未合格とする。根拠確認と訂正を行い、具体的な再テスト日は [数日後の再現を測る間隔復習を決める](https://github.com/8pockets/first-class-architect/issues/7) で決める。

## 問題を無効にする条件

次のいずれかに該当する場合、学習者を未合格にせず、問題を無効にする。条件を修正した別問題でやり直す。

- 複数の結論が主教材から合理的に成り立つ
- 判断に必要な条件が固定されていない
- 想定解と主教材の参照箇所が一致しない
- 未学習の知識がなければ解けない

## 段階表示

1回の正答を「習得済み」と呼ばず、その時点で確認できた最高段階だけを表示する。

1. 転移未確認
2. 単一条件の近い転移
3. 反例・概念境界まで確認
4. 初見統合まで確認

反例を適用できない原理では、概念識別問題の合格を3段階目とする。数日後にも再現できる「定着」の判定は、間隔復習の決定に委ねる。
